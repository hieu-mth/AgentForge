# S3 — Intelligence & Analytics (bounded local-first MVP)

## Delivered scope

AgentForge ingests user-provided CSV exports into local immutable SQLite records, computes traceable content/channel KPIs, describes internal trends, compares A/B variants without a causal winner, scores hypotheses conservatively, and separates pending amounts from owner-recorded received/paid cash. It does not claim to have live YouTube/TikTok, bank, ad, or affiliate API connections.

| Milestone | Evidence |
|---|---|
| S3.1 Input contracts | Strict UTF-8 daily metrics / cash-ledger CSVs, bounded sizes/rows, dates |
| S3.2 Provenance/import | SHA-256, timestamp, source type, demo flag; atomic append-only SQLite, duplicates rejected |
| S3.3 Content diagnosis | Views, impressions, clicks, leads, orders, watch seconds with zero-safe denominators |
| S3.4 Trends & opportunity | Historical daily data, disclosed heuristic investigation score, no market-wide claim |
| S3.5 Experiments | Two variants, same channel, overlap, approximate Wilson intervals; no causal winner |
| S3.6 Finance/affiliate | Pending vs owner-confirmed VND; verified net profit intentionally null |
| S3.7 Integration/pilot | Seven S3 skills, S1 permission/task history, localhost Dashboard, synthetic end-to-end demo |

Seven new skills: analytics.import, analytics.quality_check, analytics.content_report, analytics.trend_report, analytics.opportunity_score, analytics.experiment_report, analytics.finance_report. Reports are read-only, deterministic, with no model/network calls. Import requires workspace.write permission and confirm_write=true.

## One-pass Windows acceptance (no paid API, no browser)

Run from D:\AgentForge after pulling main:

    .\.venv\Scripts\python.exe -m pytest -q
    .\.venv\Scripts\python.exe -m agentforge.skill_registry validate
    $raw = .\.venv\Scripts\python.exe -m agentforge.analytics_pipeline demo
    if ($LASTEXITCODE -ne 0) { throw "S3 demo failed" }
    $s3 = $raw | ConvertFrom-Json
    $s3.status
    $s3.dataset
    $s3.reports.content.result.metrics
    $s3.reports.finance.result
    .\.venv\Scripts\python.exe -m agentforge.analytics_pipeline datasets
    .\.venv\Scripts\python.exe -m agentforge.task_history list

Expected: a new dataset demo-... with synthetic=true, two CSV imports,
six reports and eight task receipts. Each S1 skill task status is SUCCEEDED.
The demo data is explicitly SYNTHETIC, never real business performance.
No cloud/model/process execution, publishing, spending or bank activity.

Restart an already-running Dashboard to load code changes: Ctrl+C, then
python -m agentforge.dashboard_v0 --port 8765; open
http://127.0.0.1:8765/. It displays datasets and recorded cash (not
verified profit). GET /api/analytics exposes only safe aggregates, not
raw receipts; all mutation methods remain unavailable.

## Real import format

Put UTF-8 CSVs in workspace/analytics/inbox/ with flat ASCII filenames
(2–60 characters, letters/numbers/dash/underscore, ending .csv).
Each performance row is a DAILY per-content observation, not a cumulative
lifetime total. A conflicting second import is rejected atomically.
Dates must be ISO YYYY-MM-DD, between 2020-01-01 and today.
All counts and VND amounts must be nonnegative integers, no separators.

Performance: exact header and example:

    date,campaign,channel,content,variant,impressions,views,clicks,leads,orders,watch_seconds
    2026-10-20,nem-shorts,youtube,short-a,A,500,220,14,3,0,1980
    2026-10-20,nem-shorts,youtube,short-b,B,480,210,17,5,1,1890

Channels: youtube, tiktok, website, affiliate, other. Views are not
necessarily unique people; platform definitions can vary. Watch seconds
is total watch time for the row, not a percentage of completion.

Finance/affiliate: exact header and example:

    tx_id,date,campaign,kind,status,amount_vnd,evidence_ref
    receipt-101,2026-10-20,nem-shorts,revenue,owner_confirmed,120000,owner:receipt-101
    expected-102,2026-10-20,nem-shorts,revenue,pending,300000,
    spend-101,2026-10-20,nem-shorts,cost,owner_confirmed,45000,owner:spend-101

Owner-confirmed entries must have an owner-entered evidence reference.
They are STILL NOT bank/platform reconciled. Pending revenue is NOT cash
received. The engine never outputs verified net profit without a later
external verification and accounting reconciliation subsystem.

    .\.venv\Scripts\python.exe -m agentforge.analytics_pipeline import performance performance.csv --dataset nem-campaign --source-kind user_platform_export --confirm-write
    .\.venv\Scripts\python.exe -m agentforge.analytics_pipeline import ledger ledger.csv --dataset nem-campaign --confirm-write
    .\.venv\Scripts\python.exe -m agentforge.analytics_pipeline report content --dataset nem-campaign
    .\.venv\Scripts\python.exe -m agentforge.analytics_pipeline report trend --dataset nem-campaign
    .\.venv\Scripts\python.exe -m agentforge.analytics_pipeline report experiment --dataset nem-campaign --campaign nem-shorts
    .\.venv\Scripts\python.exe -m agentforge.analytics_pipeline report opportunity --dataset nem-campaign
    .\.venv\Scripts\python.exe -m agentforge.analytics_pipeline report finance --dataset nem-campaign

Source kind user_platform_export is owner-asserted provenance, not
authenticated retrieval. Only imported_at and sha256 are verified by code.

## Quality and interpretation boundaries

- A/B analysis needs two variants on one channel, and shows Wilson 95%
  click-rate intervals with independence assumptions; it never asserts
  random assignment, statistical superiority or an approved winner.
- An exploratory opportunity score uses 40% CTR component, 35% lead/click
  component and 25% sample coverage, multiplied by a conservative
  exposure factor. Scores are for investigation ONLY, not spending,
  business opportunity validation, or market-wide demand inference.
- Trend analysis is limited to dates in owner-supplied exports; missing
  dates, platform differences and absent attribution remain uncertainties.
- One media clip with low views cannot prove bad content quality; inspect
  distribution, creative, audience and tracking separately.
- No auto import from YouTube/TikTok, no bank integration, autonomous
  publishing, ad purchases, ROI guarantee or external revenue verification.
- Source files and databases are local/gitignored but unencrypted.
  Do not put secrets, phone numbers or personal customer data in CSVs.
  Dashboard binds to 127.0.0.1 without user authentication; do not expose
  over a tunnel or untrusted network.
- This MVP has no general ledger amendment/void workflow. Imports are
  append-only; conflicting records require owner review before correction.

S3 is DONE as a technically tested vertical slice only when Windows CI,
local demo, provenance/policy checks and Dashboard smoke test pass. Real
business acceptance additionally requires importing one genuine campaign,
reconciling data with original exports and making a documented
continue/test/stop decision. S4 must not treat a demo or heuristic report
as authorization to publish or spend money.
