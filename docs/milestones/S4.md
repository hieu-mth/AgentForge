# S4 — Company Brain & Delegation (local-first, owner-governed MVP)

## Delivery and intended boundary

S4 coordinates existing S1–S3 skills for a **bounded, explicit owner goal**:
plan -> SHA review -> approve -> dispatch child skill tasks -> stop at
permission gates -> resume only never-started waiting steps -> summarize.
Plans use **fixed and code-reviewed templates**, not open-ended LLM agent
loops. Owner approvals are not implicit spending, API, publishing or model
permissions. This MVP does not make AgentForge an unattended company.

| Milestone | Delivered scope | Verification |
|---|---|---|
| S4.1 Goal Manager | SQLite goals, immutable plan digest, explicit SHA approval | Digest mismatch and no premature execution tests |
| S4.2 Planner & Skills | Bounded templates and worker/skill selection via S1 allowlist | Reject arbitrary skill IDs, unsafe payloads and forward bindings |
| S4.3 Delegation & Queue | S1 parent workflow, one child task per step, safe dataflow from approved artifact run_id | Real read-only S3 end-to-end and consented mock media pipeline |
| S4.4 Policy & Budgets | Explicit ephemeral permission flags on EACH invocation; preflight model-call/process run *estimates* | Side effects blocked until approved; no automatic financial grant |
| S4.5 Scheduler | Local interval schedules ONLY for 100% read-only plans; once-only due slots | Confirmed/manual tick, no missed-slot replay |
| S4.6 Recovery & Memory | Dispatch markers BEFORE tool calls, explicit interrupt recovery, owner-owned evidence notes | Crash test shows interrupted, not replayed task |
| S4.7 Monitoring | Read-only local Dashboard goals and schedules, sanitized APIs | XSS, Host header, no POST, no raw input or memory leakage tests |

No new "brain skill" with arbitrary code execution was added. The central
runner remains S1's code-level fixed allowlist. Existing Skill Registry
count remains 18 skills. S4 reuses those skills, the S1 Task History, and
the S3 analytics artifacts and read-only Dashboard. No Python code,
network action, spend, browser call or OS command may be produced from
untrusted planner text.

## One-pass Windows acceptance (offline, no paid API)

From D:\AgentForge after pulling main:

    .\.venv\Scripts\python.exe -m pytest -q
    .\.venv\Scripts\python.exe -m agentforge.skill_registry validate
    $raw = .\.venv\Scripts\python.exe -m agentforge.company_brain demo --confirm-demo
    if ($LASTEXITCODE -ne 0) { throw "S4 demo failed" }
    $s4 = $raw | ConvertFrom-Json
    $s4
    if ($s4.status -ne "SUCCEEDED" -or $s4.synthetic -ne $true) { throw "S4 validation failed" }
    .\.venv\Scripts\python.exe -m agentforge.company_brain inspect $s4.goal_id
    .\.venv\Scripts\python.exe -m agentforge.company_brain list
    .\.venv\Scripts\python.exe -m agentforge.task_history list

The demo explicitly creates a fresh SYNTHETIC S3 dataset (2 imports and
6 S3 reports) and then creates, reviews, approves and executes a
4-step **read-only** "campaign.review" S4 goal using those data.
Expected: S4 goal SUCCEEDED, 4 delegated child tasks and S1 parent task,
correct audit/plan SHA, no paid API/model/browser or external publishing.
Synthetic views/revenue are never represented as real business evidence.

Restart a running Dashboard V0 to load new code (Ctrl+C in server terminal):

    .\.venv\Scripts\python.exe -m agentforge.dashboard_v0 --port 8765

Then refresh http://127.0.0.1:8765/.
New sections: S4 Company Goals and Local Schedules, with sanitized read-only
GET /api/goals, /api/goals/<id>, /api/schedules. The interface intentionally
does not grant tool permissions, start jobs or expose full inputs/owner notes.

## Owner goal workflow: campaign review

Prepare a local JSON file, e.g. workspace/goal-input.json:

    {"dataset":"demo-EXISTING-ID","campaign":"nem-shorts"}

Then:

    $draftRaw = .\.venv\Scripts\python.exe -m agentforge.company_brain propose campaign.review --title "Review mattress campaign" --input-file .\workspace\goal-input.json
    if ($LASTEXITCODE -ne 0) { throw "Cannot plan goal" }
    $draft = $draftRaw | ConvertFrom-Json
    .\.venv\Scripts\python.exe -m agentforge.company_brain inspect $draft.goal_id
    .\.venv\Scripts\python.exe -m agentforge.company_brain approve $draft.goal_id --sha256 $draft.plan_sha256
    .\.venv\Scripts\python.exe -m agentforge.company_brain run $draft.goal_id

Planning alone NEVER executes. Approval of SHA authorizes the exact plan,
but each owner-gated tool requires fresh permission grants and applicable
confirmations in addition to plan approval. No blanket automation.

Supported templates:

- campaign.review: analytics quality, content performance, opportunity
  hypotheses, owner-recorded finance (4 read-only skills)
- website.campaign: local web static quality + 4 campaign insights
- website.browser: static quality + separately consented browser validation
- media.produce: compose frames -> quality -> consented FFmpeg video;
  outputs are bound by a checked previous run_id, not arbitrary expressions
- media.review: quality report for an existing S2 media run
- research.discovery: existing search/model research action, requires
  explicit max_model_calls and S1 network/model grants
- creative.storyboard: one owner-approved model draft, NOT auto-published

To create a media plan, add --max-external-runs 1 to propose. Running without
workspace.write leads to WAITING_APPROVAL (CLI exit code 3). Resume with
--grant workspace.write. The FFmpeg step waits for workspace.write and
process.run PLUS --confirm-external-run; no approvals persist between CLI
invocations. A research/storyboard plan similarly needs --max-model-calls 1,
model.invoke plus independent --confirm-model-call (and any network/write
permissions). These are **estimates and preflight limits**, not hard
token-level or monetary metering; actual costs need later instrumentation.
Owner should not authorize cloud calls unless they accept costs.

## Local scheduler and recovery

Scheduling is not a daemon and no operating-system cron/task scheduler is
installed by S4. Example of explicit standing authorization to check a
read-only dataset every 60 minutes (time must be in the future):

    .\.venv\Scripts\python.exe -m agentforge.company_brain schedule create campaign.review --title "Review campaign" --input-file .\workspace\goal-input.json --next-due 2026-11-07T09:00:00+07:00 --every-minutes 60 --confirm-schedule
    .\.venv\Scripts\python.exe -m agentforge.company_brain schedule list
    .\.venv\Scripts\python.exe -m agentforge.company_brain schedule tick --confirm-tick

Tick only executes DUE, previously authorized read-only plans. It
records a unique schedule slot before execution; missed intervals are
skipped, not replayed automatically. External Windows Task Scheduler
would need to be configured separately by the owner on an always-on
machine to keep firing ticks. No unattended 24/7 capability is claimed
by this milestone.

After a crash or power loss, a RUNNING goal may have executed a tool but
not saved its result. Never rerun it automatically. Inspect manually:

    .\.venv\Scripts\python.exe -m agentforge.company_brain list
    .\.venv\Scripts\python.exe -m agentforge.company_brain recover --confirm-recover

This marks potentially ambiguous work INTERRUPTED, including matching S1
running child/parent tasks, while leaving unrelated S1 tasks untouched.
Interrupted, failed and finished goals cannot be replayed; the owner may
create a NEW goal after inspecting side effects and artifacts.

Memory is an owner-controlled evidence notebook, not automatically
mined chat history, a credential store or a vector-RAG engine:

    .\.venv\Scripts\python.exe -m agentforge.company_brain memory set marketing.goal --note "Focus on verified inquiries" --evidence-ref owner:interview-1 --confirm-write
    .\.venv\Scripts\python.exe -m agentforge.company_brain memory list

## Security / truthfulness / next milestones

- Inputs and memory are stored in local unencrypted SQLite
  (data/company/s4_brain.sqlite3). Never put passwords, token values,
  customer identity or confidential documents in goal inputs/notes.
- Dashboard is unauthenticated and bound ONLY to 127.0.0.1. Never tunnel
  or expose it remotely. Its read-only APIs show statuses, not raw
  plan inputs, memory contents or skill output.
- Budget caps are plan-level declared model/process call hints, not a
  hard currency/token ledger. Do not claim operational spending control
  until instrumented against actual external providers.
- The planner is deterministic and template-limited to 6 steps. It does
  not independently invent new business strategies, install skills,
  create social channels or schedule itself continuously.
- S4 never turns synthetic S3 analytics into verified demand/profit.
- S5 will need explicit, authenticated platform connectors, owner
  approval, financial reconciliation, outcome tracking, and only
  evidence-driven closed-loop optimizations before production operation.

S4 is "MVP technically complete" only after Windows CI and owner local
demo/dashboard acceptance, not equivalent to a fully autonomous company.
