# S1 — Skill Execution Foundation (S1.1–S1.7)

**Scope:** Complete the minimum local-first vertical slice of Skill Registry,
Skill Adapters, Task History, bounded workflow, Permission Gate v0,
Dashboard V0 and an end-to-end pilot. This is not a general autonomous
company brain, an OS sandbox, a payment/budget engine or a remote service.

## Implemented

| Milestone | Implementation | Boundaries |
|---|---|---|
| S1.1 Contract/Registry | Five TOML skill descriptions, validation, discover/inspect | Registry does not execute |
| S1.2 Adapters | One skill_runner.invoke API for five allowlisted C7/C8 functions | No dynamic import from TOML |
| S1.3 Task History | Local s1_tasks.sqlite3, task states, append-only events, parent-child links | No automatic replay |
| S1.4 Workflow | web.audit: static quality, optional browser, SHA checkpoint and resume | One bounded workflow |
| S1.5 Permissions v0 | Code-level allowlist, exact grants and model/browser confirmations | Local owner CLI only |
| S1.6 Dashboard V0 | Read-only localhost HTTP UI and limited JSON APIs | No task mutation or deployment |
| S1.7 Pilot | Actual static website checks and mocked browser/adapter integration tests | Live aesthetic QA remains manual |

The existing C8A proposal and digest-confirmed apply remain separate:
web.create never automatically applies or deploys. Browser checks execute
untrusted JavaScript in Playwright; this is not an OS sandbox. No automatic
model retry, financial transactions, posting, package installation or shell commands.

## Permission policy

POLICY in skill_runner.py binds each skill to a worker, mode and mandatory
permission set independently of TOML.

- Read-only quality checks implicitly receive only workspace.read.
- web.create: model.invoke + workspace.propose and --confirm-model-call.
- research.opportunity: model.invoke + network.search + workspace.write
  and --confirm-model-call.
- research.source_review: workspace.write + network.read + model.invoke,
  explicit allowed_hosts, input approve_read_only=true and --confirm-model-call.
- web.browser_test: browser.run and --confirm-browser-run, plus input
  confirm_browser_run=true. Playwright must be separately installed.

Denied tasks become WAITING_APPROVAL and never execute. Only unstarted
waiting skill tasks may resume; completed, failed or interrupted tasks cannot
automatically replay side effects. Grant flags are NOT a multi-user authentication
service or proof that underlying modules cannot be invoked outside this runner.

Resource hints such as timeout_seconds and estimated model calls remain
declarative: hard timeouts/financial budgets are not yet enforced.

## One-pass Windows acceptance (without model/browser)

From D:\AgentForge after git pull:

    .\.venv\Scripts\python.exe -m pytest -q
    .\.venv\Scripts\python.exe -m agentforge.skill_registry validate
    .\.venv\Scripts\python.exe -m agentforge.skill_runner invoke web.quality_check --slug nem-tu-van
    .\.venv\Scripts\python.exe -m agentforge.workflow_runner run nem-tu-van
    .\.venv\Scripts\python.exe -m agentforge.task_history list
    .\.venv\Scripts\python.exe -m agentforge.dashboard_v0 --port 8765

In another PowerShell window:

    Invoke-Item "http://127.0.0.1:8765/"

Expected: VALID with five manifests, a working web audit for a local
nem-tu-van/index.html, SQLite parent/child events and the read-only dashboard.
If HTML has static FAIL findings, audit must report FAILED and stop.

Optional separate owner-approved browser audit:

    $raw = .\.venv\Scripts\python.exe -m agentforge.workflow_runner run nem-tu-van --browser
    $pending = $raw | ConvertFrom-Json
    # Exit code 3 means WAITING_APPROVAL; browser has not run
    .\.venv\Scripts\python.exe -m agentforge.workflow_runner resume $pending.task_id --grant browser.run --confirm-browser-run

PowerShell argument quoting for JSON varies: prefer --input-file for general
skill invocations. For example, create a UTF-8 JSON file containing the keys
slug and brief, then call:

    .\.venv\Scripts\python.exe -m agentforge.skill_runner invoke web.create --input-file .\skill-input.json --grant model.invoke --grant workspace.propose --confirm-model-call

Do not use an existing slug or call a paid model without consent. This makes
a proposal only; use C8A inspect and apply for owner-approved product writes.

## Recovery, privacy and limitations

task_history show <task_id> prints recorded task/events.
task_history recover --confirm-recover marks abandoned RUNNING tasks
INTERRUPTED without replaying actions. The workflow browser step checks
the website source SHA before using a previous quality checkpoint.

The local data/company/s1_tasks.sqlite3 database is not encrypted and
can store task input briefs/URLs: never place secrets in skill payloads.
Dashboard binds 127.0.0.1, omits prompts and raw task outputs, and has no
authentication: do not expose it to networks, tunnels or shared machines.

S1 is completed as this bounded local-first slice, NOT as a generic
multi-agent planner, certified browser sandbox, OS resource manager,
credential vault, authenticated API or autonomous revenue engine.
