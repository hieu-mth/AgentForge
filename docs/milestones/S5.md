# S5 — Revenue & Growth Operations (bounded local-first MVP)

S5 closes a **human-in-the-loop** business workflow spanning S2 media,
S3 analytics source evidence, S4 Company Brain, and S1 task approvals.

**Important scope boundary:** S5 generates owner-reviewed YouTube Shorts
and TikTok manual-upload packages, tracks consent-attested anonymous leads,
owner-entered commissions/costs and public URL attestations, and reports
business outcomes. It DOES NOT create accounts, upload through platform
APIs, access banking, verify post existence or initiate payments.

| Vertical slice | Capability | What it does NOT prove |
|---|---|---|
| Campaign | Local SQLite campaign + owner-recorded VND cost cap | Provider-side spend limit |
| Publishing | Verified S2 MP4/SRT/post copy zipped for owner upload | Actually uploaded/approved by YouTube/TikTok |
| Channel evidence | Canonical HTTPS permalink supplied by owner | Authenticated API response |
| Leads | Consent-attested anonymous lead IDs/states | Unique verified customers or attribution |
| Commission | Immutable pending/owner-confirmed bookkeeping events | Payment or net profit verified |
| Reconciliation | Cross-check S5 entries with owner-imported S3 ledger | Bank/platform reconciliation |
| Brain | Three-step S4 growth.review goal | Unbounded autonomous campaign operation |
| Dashboard | Read-only S5 campaign summaries | Authenticated multi-user management |

There are six S5 skills: growth.campaign_create, growth.bundle_prepare,
growth.record_event, growth.report, growth.quality_check, growth.reconcile.
Skill Registry grows from 18 to 24 skills. Every local write requires
workspace.write and an independent confirm_write=true. Upload preparation
additionally requires confirm_rights=true. Existing S1 owner-gated
execution and task history are reused, with no unrestricted worker.

## Real use: owner-provided campaign, handoff and outcomes

Create workspace/s5-campaign.json with:

    {
      "campaign": "nem-website",
      "title": "Tư vấn chọn nệm",
      "analytics_dataset": "",
      "budget_vnd": 100000,
      "synthetic": false
    }

    .\.venv\Scripts\python.exe -m agentforge.growth_pipeline campaign-create --input-file .\workspace\s5-campaign.json --confirm-write

budget_vnd limits only owner-entered COST rows; it DOES NOT stop any
real advertising provider from charging. Set zero for a no-cost pilot.
Optional analytics_dataset must exist in S3 with the same synthetic flag.

Produce a real S2 MP4 first and copy its 32-character run_id. Prepare
workspace/s5-bundle.json:

    {
      "campaign": "nem-website",
      "channel": "youtube",
      "run_id": "0123456789abcdef0123456789abcdef",
      "title": "Gợi ý chọn nệm phù hợp",
      "description": "Các yếu tố nên cân nhắc khi chọn nệm."
    }

    .\.venv\Scripts\python.exe -m agentforge.growth_pipeline bundle --input-file .\workspace\s5-bundle.json --confirm-rights --confirm-write

The run_id above is a PLACEHOLDER. The bundle requires a real
VIDEO_PASS MP4 and owner confirmation of image/music/product rights.
ZIP files contain video.mp4, captions.srt, post.txt and manifest.json.
Review yourself and upload through a legitimately owned channel.
Use channel=tiktok for an independently prepared TikTok bundle.
There are NO platform OAuth credentials or outbound upload actions.

Record a consented anonymous lead by saving workspace/s5-event.json:

    {
      "kind": "lead_new",
      "data": {
        "campaign": "nem-website",
        "channel": "website",
        "consent_confirmed": true
      }
    }

    .\.venv\Scripts\python.exe -m agentforge.growth_pipeline record-event --input-file .\workspace\s5-event.json --confirm-write

Do not attest consent unless actually obtained. This system records an
opaque lead_id, channel and state only. It rejects names, phone numbers,
email addresses, messages and other extra JSON fields. Keep actual
customer communication in a separate appropriately protected CRM.
Lead states: NEW -> CONTACTED/QUALIFIED/LOST; CONTACTED ->
QUALIFIED/LOST; QUALIFIED -> WON/LOST.

Only AFTER uploading manually may the owner save a post_attest event:

    {
      "kind": "post_attest",
      "data": {
        "package_id": "0123456789abcdef0123456789abcdef",
        "url": "https://www.youtube.com/shorts/AbCdEf12345",
        "confirm_owner_posted": true
      }
    }

S5 validates canonical YouTube Shorts / TikTok public URL patterns.
It NEVER fetches URLs. OWNER_REPORTED_POSTED means only an owner claim,
not platform API verification. Never supply tokens/query parameters.

Commission or cost event example:

    {
      "kind": "money",
      "data": {
        "campaign": "nem-website",
        "tx_id": "commission-001",
        "kind": "commission",
        "status": "pending",
        "amount_vnd": 50000,
        "evidence_ref": "",
        "s3_tx_id": ""
      }
    }

Kinds: commission/cost. Status: pending/owner_confirmed.
Owner-confirmed rows require an owner-entered evidence_ref. This is NOT
bank proof. An optional s3_tx_id crosschecks a corresponding S3 ledger
row, matching campaign, source dataset, kind, amount and status. S3
records are themselves owner-imported and not bank verified.

    .\.venv\Scripts\python.exe -m agentforge.growth_pipeline report nem-website
    .\.venv\Scripts\python.exe -m agentforge.growth_pipeline quality nem-website
    .\.venv\Scripts\python.exe -m agentforge.growth_pipeline reconcile nem-website

Company Brain supports the fixed read-only template growth.review.
Create a goal input JSON {"campaign":"nem-website"} then use S4
propose -> inspect -> approve by SHA -> run. No hidden authorization.

## Non-negotiable limitations

- No account creation, autonomous publishing, YouTube/TikTok OAuth/API,
  comment moderation, analytics polling, ads or recurring posting.
- No payment initiation, banking integration, independently verified
  revenue or full profit accounting (taxes, refunds, completeness).
- Local bookkeeping budgets are not enforceable provider-side budgets.
- This milestone proves the *software* workflow, not actual customers or
  commerce; a real pilot still requires owner-uploaded content and real,
  consented source evidence.
- SQLite and source files are local but unencrypted; do not store PII,
  tokens or passwords. Dashboard is unauthenticated and localhost-only.
- To meet the ultimate always-running business vision, later work must
  add legitimate authenticated platform connectors, reconciliation,
  actual cost enforcement, deployment, monitoring, and an owner-operated
  read/write Control Center. Passing all five MVPs does not imply those
  production capabilities already exist.
