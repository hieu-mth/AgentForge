# S1.1 — Declarative Skill Contract & Registry

## Status
Implemented as **discovery/validation only**. A manifest does not execute
code, authorize spending, grant permissions, or validate a real outcome.
The execution gateway and SQLite task history are separate S1.2/S1.3 milestones.

## Design
- Standard-library TOML manifests: skills/<skill_id>/skill.toml.
- Single registry loader: agentforge.skill_registry. No dynamic imports, arbitrary
  command strings, plugin installation, or remote manifests.
- Strict allowed fields, semantic version, names, permissions and resource hints.
- Input/output *shallow* object schemas: primitive types plus array/object top-level
  checks. This is an intentionally limited subset, not full JSON Schema validation.
- Paths reject symlinks/junctions; size-bounded manifests; no filesystem writes.
- Permissions and limits are **declarations, not enforced runtime grants**.
- Worker registry remains separate: worker is an actor; skill is a reusable
  capability. These contracts name existing workers but don't create new ones.
