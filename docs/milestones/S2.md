# S2 — Creative & Media Engine (local-first MVP)

## What is implemented

| Step | Capability | Actual output / safety boundary |
|---|---|---|
| S2.1 | Content / storyboard | Owner-provided 2–5 scenes or one-model **draft for review** |
| S2.2 | Image create + edit | Original 540 × 960 PNG scene cards, non-destructive tint/contrast edits; optional licensed owner photo |
| S2.3 | Audio / TTS | Original WAV sound bed; optional offline Windows vi-VN SAPI or local Piper voiceover |
| S2.4 | Caption | UTF-8 timed SRT sidecar and captions rendered visibly in scene images |
| S2.5 | Video production | Real vertical MP4 (H.264/AAC) assembled by explicit local FFmpeg subprocess |
| S2.6 | Media QA | SHA-256, Pillow decode, WAV PCM/duration, SRT count/timing, MP4 boxes + actual FFmpeg audio/video stream decode |
| S2.7 | S1 integration | Six new media skill manifests, hard-coded permission policy, SQLite Task History, tested one-shot demo |

Six S2 skills: media.compose, media.image_edit, media.quality_check,
media.video_render, media.tts, media.copy_draft.
The existing five research/web skills and workflows remain unchanged.

S2 is a **bounded usable media-production MVP**, not general-purpose
text-to-video diffusion, an unrestricted editor, deepfake/voice cloning,
automatic cloud image generation, a publishing agent or a marketing analytics
system. Text/image results require human editorial and rights review.

## One-pass Windows test (no external API, no model, no voice required)

From D:\AgentForge after pulling the new main commit:

    .\.venv\Scripts\python.exe -m pip install -e ".[media]"
    .\.venv\Scripts\python.exe -m pytest -q
    .\.venv\Scripts\python.exe -m agentforge.skill_registry validate
    $raw = .\.venv\Scripts\python.exe -m agentforge.media_pipeline demo nem-s2-pilot --render-video --confirm-media-run
    if ($LASTEXITCODE -ne 0) { throw "Media demo failed" }
    $result = $raw | ConvertFrom-Json
    $result
    $runId = $result.assets.result.run_id
    .\.venv\Scripts\python.exe -m agentforge.media_pipeline check $runId
    Invoke-Item $result.video.result.video_path
    .\.venv\Scripts\python.exe -m agentforge.task_history list

Expected: PNGs, ambient.wav, captions.srt, video.mp4, task receipts,
static QA status VIDEO_PASS, and an actual playable vertical video.
The demo content is original and contains no invented price/warranty/brand.
The synthetic ambient bed is **not** a spoken narration.

Media extra downloads at installation time (Pillow + imageio-ffmpeg,
approximately 40 MB of FFmpeg Windows wheel). Runtime does not download
models, fetch images or call cloud services. Media operations remain local.
All outputs live under workspace/media/<run_id>, are never published,
and are not committed to Git (workspace is ignored).

## Owner-provided storyboard / optional photo

Create an input file, for example workspace/media_story.json:

    {
      "slug": "nem-campaign",
      "title": "Tư vấn nệm",
      "scenes": [
        {"headline": "Chọn nệm", "caption": "Hãy cân nhắc nhu cầu sử dụng.", "duration_seconds": 4},
        {"headline": "Liên hệ", "caption": "Trao đổi để chọn sản phẩm phù hợp.", "duration_seconds": 4}
      ]
    }

    .\.venv\Scripts\python.exe -m agentforge.media_pipeline create --input-file .\workspace\media_story.json --render-video --confirm-media-run

For a photo, first copy a personally owned/appropriately licensed PNG/JPEG
into workspace/media_inputs/ (flat ASCII filename, max 12 MB). Add
"photo_name": "my-photo.jpg", "rights_confirmed": true to the input JSON.
Rights are **owner-attested, not independently validated**. Never use
customer photographs without permission. No remote URLs are allowed.

## Explicit offline voiceover (optional)

Use create **without** --render-video to obtain run_id, then before render:

    .\.venv\Scripts\python.exe -m agentforge.media_pipeline tts <run_id> --engine windows --confirm-media-run
    .\.venv\Scripts\python.exe -m agentforge.media_pipeline render <run_id> --confirm-media-run

Windows requires an enabled preinstalled Vietnamese vi-VN SAPI voice.
No voice is silently substituted if unavailable. Alternatively install
Piper yourself and place an approved flat .onnx voice and matching
.onnx.json under models/voices/ (gitignored/local). Then run:

    .\.venv\Scripts\python.exe -m agentforge.media_pipeline tts <run_id> --engine piper --voice YOUR_VOICE.onnx --confirm-media-run

The system validates WAV encoding and length; it does **not** certify
phonetic quality, language accuracy or word-level subtitle alignment.
The SRT uses fixed scene durations, not automatic speech recognition.
Adjust narration/scene durations manually before final use.

The one-model media.copy_draft skill requires model.invoke and
workspace.propose grants plus --confirm-model-call. Its result is explicitly
DRAFT_NOT_VERIFIED and is never auto-rendered. Owner review is required.

## Security & quality

- The centralized S1 policy checks explicit workspace.write and
  process.run grants plus independent confirm_external_run before video/TTS.
- Media paths and run IDs are constrained; no arbitrary shell arguments,
  remote image URLs, executable HTML or downloaded models.
- FFmpeg processes run via fixed argv with shell=False and bounded timeout;
  they are **not** an OS sandbox. Owner must trust installed binaries
  and source media.
- Source photos are decoded with Pillow under strict file/pixel budgets.
- Existing media runs and videos are immutable; edits produce new files.
- SHA mismatch or media corruption causes QA FAIL and prevents new encoding.
- VIDEO_PASS proves structural/decoding checks, **not** aesthetic quality,
  truthful marketing claims, legal music/image rights or conversion.

## Remaining for business deployment

Inspect output on a phone and listen to audio; replace synthetic bed with
an appropriately licensed track or approved voice if needed. Confirm
accessibility, brand/rights, click-through goal and product claims.
No social channel posting, cloud model subscriptions, analytics/ROI or
verified revenue tracking is implemented; those belong to S3–S5.
